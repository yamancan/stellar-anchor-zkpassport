The Solution
[ TRIONLABS ]

Document conditions become
proofs applications can use.

Define the rule.

An age threshold, an allowed document country, or a supported list check.

Verify the proof.

A pinned Soroban verifier checks the ZKPassport proof.

Use the result.

The application uses the accepted condition in its access or transaction rules.

Current application: a Testnet anchor. Sybil and multi-proof scenarios require further development.

PMF
[ TRIONLABS ]

Finding out too late that
an applicant is ineligible costs more.

Example: rejecting an underage applicant only after a lengthy document flow.

Verification spend

Unnecessary billable verifications can consume the operating budget.

User effort

Users upload documents and complete the steps, only to learn they are ineligible.

Unnecessary data

Excess document data may be collected even from applicants who never become customers.

Savings are a hypothesis. We do not assume every failed check is billed or every institution stores documents.

A02 / 09
[ TRIONLABS ]APPENDIX / SYBIL LIMITS

Four issues to resolve
for Sybil resistance.

SOURCE

Same document or same person?

Define multiple-document, renewal, and person-document binding rules.

SCOPE

Once in which program?

Scope the nullifier to the campaign and entitlement type.

RECORD

Which entitlement was used?

Persist successful claims and protect against reuse.

PRIVACY

Can activity be linked across apps?

Assess whether the identity marker can be tracked across programs.

Order replay protection does not replace campaign-level Sybil resistance.

A03 / 09
[ TRIONLABS ]APPENDIX / SCREENING SCOPE

State precisely what
a screening result means.

Which dataset?

Record the list’s source, version, and date. A pinned root is not a current list.

Which matching method?

Exact address matching differs from name/identity screening. Exact matching alone cannot establish a broader result.

Valid when?

Separate proof validity from list freshness. A valid proof does not update an old dataset.

“No match under this list and rule” ≠ “compliant with all sanctions.”

This prototype’s list check is not real-person verification or current production compliance approval.
